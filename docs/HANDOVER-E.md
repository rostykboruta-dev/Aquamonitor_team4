## 1. Зроблено
* Створено модуль `src/aquamonitor/cli.py` із використанням стандартного модуля `argparse`.
* Реалізовано структурований інтерфейс командного рядка з підкомандами `fetch`, `forecast` та `report`, а також обов'язковими й додатковими аргументами (`--input`, `--sensor`, `--window`, `--config`).
* Реалізовано функцію `load_config(config_path)`, яка підтримує парсинг файлів конфігурації у форматах `.json` та `.ini`.
* Написано та успішно запущено юніт-тести в `tests/test_cli.py`.
## 2. Не зроблено
* Декоратор заміру часу виконання `@timed` у `src/aquamonitor/infra.py`.
* Функція налаштування логування `setup_logging()`.
* Підключення бізнес-логіки обробки даних із модулів `dataio.py`, `core.py` та `analytics.py` до команд CLI (наразі виводяться інформаційні повідомлення).

## 3. Ухвалені рішення
* Шлях до файлу конфігурації за замовчуванням встановлено як `config.json`.
* Якщо файл конфігурації відсутній, програма виводить попередження та повертає порожній словник `{}` замість аварійного завершення.
* Для непідтримуваних розширень файлів конфігурації викидається `ValueError`.

## 4. Проблеми
* При поверненні порожнього словника конфігурації інші модулі повинні мати значення за замовчуванням для всіх критичних параметрів.

## 5. Далі
* Зв'язати команди CLI (`fetch`, `forecast`, `report`) із реальним функціоналом завантаження даних, аналізу та створення звітів.
* Реалізувати модулі `timed` та `setup_logging` у `infra.py`.

## 6. Обережно
* Під час розширення CLI зберігайте структуру підкоманд відповідно до `spec.md`.
* Під час тестування CLI через `unittest` ізолюйте `sys.argv` за допомогою `patch("sys.argv", ...)` для уникнення конфліктів із параметрами запускника тестів.

## 7. Як запустити
1. Переконайтеся, що ви перебуваєте в корені репозиторію та активовано віртуальне середовище (`.venv`).
2. Запустіть тести CLI через `unittest` у **Git Bash**:
   ```bash
   PYTHONPATH=src python -m unittest tests/test_cli.py
